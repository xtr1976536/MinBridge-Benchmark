# Public analyst-question source audit

Audit date: 2026-10-22. This document targets the MinBridge proposal's independently annotated set of about 300 real analyst questions. It distinguishes three provenance classes:

- **Observed professional inquiry:** a question actually submitted to a financial research service or spoken by an analyst on an earnings call.
- **Expert-authored benchmark item:** written by a practitioner or finance expert for an evaluation. Realistic, but not a historical user question.
- **Generated or templated item:** model-written or filled from a fixed question template.

For the original MinBridge claim, the first class is the strongest. A dataset can be public and expert-annotated yet still lack any labels for whether the question is answerable from a *specified* document, what numerical relation is justified, or which fact is missing. Those are new annotations.

The [FinDER paper](https://arxiv.org/html/2504.15800v2) explicitly describes the source as a professional Q&A service database and says queries lacking 10-K evidence were filtered out. The type breakdown is `None` 4,820; `Compositional` 440; `Division` 128; `Multiplication` 121; `Subtract` 111; `Addition` 75; `Subtraction` 8. All 5,703 question strings were unique. The 883 operational-type rows are *candidates*, not 883 verified MinBridge items.

## Excluded leads and why

- [Lamini earnings-calls-qa](https://huggingface.co/datasets/lamini/earnings-calls-qa) is large (860,164 rows, CC BY 4.0), but its [generation pipeline](https://github.com/lamini-ai/lamini-earnings-calls) creates questions from transcripts. It is **synthetic QA**, not questions spoken by analysts. Sample rows also include explicit “I do not know” answers; avoid using them as gold labels without checking context.
- [nsmofficial finrag-bench](https://github.com/nsmofficial/finrag-bench) README describes 500 curated questions, but the checked `questions.jsonl` contains only one `Q-PLACEHOLDER` record. The public 50-row smoke file should not be represented as the full benchmark.
- FinQA and TAT-QA are valuable numerical QA datasets but their questions were authored for data collection. They are not historical analyst requests.
- Reddit, Stack Exchange and general investing forums contain authentic public questions, but author profession is usually unverifiable and evidence/answer rights vary. They may support exploratory language analysis, not a benchmark claimed to contain analyst questions.

## Practical 300-question construction

1. **Primary pool:** Start from the 883 FinDER rows with an operation type. Preserve the original `_id`, exact query, evidence references and answer; do not paraphrase before eligibility review. Exclude rows whose query asks for forecasts, broad explanations, multi-part commentary or a value merely copied from a table. Do not assume that `type` is correct; samples show misclassified operation labels.
2. **Context definition:** Freeze the disclosure set each question may use, ideally the linked 10-K and, when needed, its specific year. Without a fixed boundary an “unanswerable” label is not meaningful. Keep the originally released FinDER task answerable, then assess answerability independently under the MinBridge context.
3. **Gold review:** For each retained row, annotate target metric/entity/period/unit, operand spans, accepted relation(s), numerical result or refusal reason, and whether an alternate valid relation exists. Two finance-capable annotators independently review and adjudicate. Only then can a sample count toward the 300.
4. **Backup pool:** If fewer than 300 FinDER questions pass, supplement with analyst speech extracted from STRUX or EvasionBench, linking to a public company-hosted transcript or authorized source. Review rights before publishing verbatim text. Record `provenance_class=observed_earnings_call` separately from `observed_service_query`.
5. **Separate external challenge:** Keep FinSearchComp, FinanceBench, Vals and BigFinanceBench outside the primary 300 and outside SCPO training. Report them as expert-authored external tests with their own task scope, so the primary claim about *observed* analyst questions remains defensible.

No current source directly provides 300 genuine analyst questions with MinBridge's answerability, relation-provenance and minimal-certificate annotations. The research bottleneck is **annotation and context checking**, not finding raw question strings. If 300 genuine numerical questions are the strict target, FinDER makes this plausible from an 883-row candidate pool, but the final yield remains unknown until screening. Published benchmark totals of 537, 928, 999 or 10,231 should never be used as available sample counts without checking the released files.
